# AGENTS.md

Solidity port of [ensdomains/address-encoder](https://github.com/ensdomains/address-encoder).
Converts chain addresses to and from the bytes ENS stores in `addr(node, coinType)`.

## Toolchain

- Foundry, compiled with **Solar** (`solc = "solar:0.3.1"` in `foundry.toml`), not solc.
- `forge build`, `forge test`, `forge fmt`, `forge lint`. CI runs `fmt --check`, `lint`, `build --sizes` and `test`.

## Layout

- `src/<Chain>Coder.sol`: one library per chain (see the README table). Each one exposes
  `encode(bytes) → (bool ok, string addr)`, `decode(string) → (bool ok, bytes data)` and `COIN_TYPE`
  (`EvmCoder` has `COIN_TYPE_ETH` / `COIN_TYPE_DEFAULT`, per ENSIP-19).
- `src/AddressCoder.sol`: opt-in dispatcher by coinType over every coder.
- `src/utils/`: shared building blocks (`Base58`, `Base32`, `Bech32`, `BitcoinLike`, `CashAddr`, `Blake2b`, `SS58`).
- `test/Coders.t.sol`: vector, decode-only, invalid-input and round-trip fuzz tests, run through a `Harness`
  that calls `AddressCoder`. `test/Blake2b.t.sol` has RFC 7693 and hashlib vectors.
- `test/vectors/`: `vectors.json` is generated by `generate.mjs` from the JS reference. Don't hand-edit it.

## Conventions

- **Everything is an `internal` library function.** That's what keeps the libraries tree-shakeable: a
  consumer only compiles in the coders and functions it calls. Don't add `public`/`external`
  library functions or storage. `AddressCoder` is the only file that imports every coder, and no
  coder or util may import it.
- One file per chain. Adding a chain shouldn't change the bytecode of contracts that use other coders.
- Byte layout must match `@ensdomains/address-encoder` (the output of `decode`, the input of `encode`).
  Being stricter about validity is fine; document any difference in the README.
- **Nothing reverts, and there are no custom errors.** `encode` and `decode` return `(false, "")` on
  invalid input, and so does every util that can fail. Internal library calls can't be wrapped in
  `try`/`catch`, so a revert would leave callers no way to handle bad input. Don't index past a
  length you haven't checked (a panic is a revert too). `testFuzz_encodeNeverReverts*` and
  `testFuzz_decodeNeverReverts*` enforce this for every coinType.
- Coders are `pure` unless they need a precompile (Polkadot/Kusama use the BLAKE2b precompile, so they're `view`).
- If the reference has a bug, don't copy it. Write a vector that pins the correct behaviour, and record
  the difference in the README.
- New Bitcoin-style chains should wrap `BitcoinLike` with their HRP and version bytes. Chains
  without SegWit should use `encodeLegacy`/`decodeLegacy`, so the bech32 code isn't compiled in.
- Check bytecode with a throwaway contract and `forge build --sizes`: a coder shouldn't pull in
  code it can't reach.

## Adding a coder

1. Add `src/<Chain>Coder.sol` (and any shared util under `src/utils/`). Give the library NatSpec with a
   `References:` list: the format specs, where the chain's constants come from, and the
   address-encoder source file. Wire it into `AddressCoder` (`encode`, `decode`, `isSupported`).
2. Add a `define('<coin>', …)` block to `test/vectors/generate.mjs` with `valid`, `decodeOnly`
   (non-canonical forms), `invalidAddress` and `invalidBytes` cases, then regenerate:
   `cd test/vectors && npm i --no-save @ensdomains/address-encoder && node generate.mjs`
3. In `test/Coders.t.sol`, add a `test_<coin>_vectors` test, the coinType to `_coinType` and
   `test_isSupported`, and fuzz round-trips.
   Update the README table.
